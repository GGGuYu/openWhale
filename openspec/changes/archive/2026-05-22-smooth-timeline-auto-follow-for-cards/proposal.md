## Why

当前聊天时间线的自动跟随体验还不完整：文字流式更新时会下滚，但工具调用产生的卡片、输出型结果卡片和其他结构化时间线条目出现时，不一定会像正文一样自然跟随到底部。同时，现有跟随动作偏“瞬间跳到底”，用户在贴近底部观看连续输出时，会感到滚动生硬、不连贯。

## What Changes

- 明确自动跟随不仅适用于文本增量流式更新，也适用于 tool feedback、option / route / hotel 等输出型卡片以及其他新增时间线条目。
- 要求当用户仍贴近底部时，时间线使用平滑动画方式跟随最新内容，而不是以突兀的瞬时跳转完成对齐。
- 保留现有“用户主动上滑后不被强制拉回底部”的约束，避免打断用户查看历史内容。
- 为后续实现补充可验证的规格与任务拆解，使这部分滚动体验作为独立变更处理。

### Modified Capabilities

- `mobile-agent-runtime`: 收紧时间线 auto-follow 要求，覆盖非文本卡片/工具输出，并要求贴底状态下使用平滑动画跟随最新内容。

## Impact

- 受影响代码主要位于聊天时间线滚动与渲染相关的 Compose UI，例如 `app/src/main/java/com/example/openwhale/ui/main/MainScreen.kt`。
- 可能影响时间线尾部锚点判定、结构化卡片插入后的滚动触发，以及流式/多阶段 tool loop 期间的滚动节奏控制。
- 需要补充 UI 自动化或人工验收，覆盖“贴底时平滑跟随”“离开底部时不打断”两类行为。
